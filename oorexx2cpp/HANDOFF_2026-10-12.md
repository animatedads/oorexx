## Shared strings (Tom: "ooRexx exclusively uses references")

`rx::Value::bytes` is an `rx::RxStr`: a string longer than 64 bytes lives in one shared buffer, so copying a Value
(BIF argument, assignment, PARSE source, message argument, stem element) copies a pointer. A writer that finds the
buffer shared takes its own copy first (`mut()`). Short strings stay inline. RxStr has the read interface of
std::string and converts to `const std::string &`; in a `?:` with a std::string use `.str()` (a mixed `?:` copies).
Effect (shared strings alone; branch `wip/parse-source-ref` is superseded, not merged): 200 KB `parse value ... with =(p) c +1`
loop 1.1 s -> 0.12 s (interpreter 0.38 s).

## Interpreted table (`<package>.rx2cpp`)

Tom's compatibility table for the native package lane. `native/build.sh` uses `RX2CPP_TABLE=path`, else
`<source>.rx2cpp` next to the source. One rule per line (`#` / `--` comments):
```
prefer_interpreted   Class                 whole class interpreted
prefer_interpreted   Class  method         one instance method
prefer_interpreted   Class  method  CLASS  one class method
requires_interpreted ...                   same forms; the build fails if it cannot be honoured
```
- A whole class goes unchanged into the library's declaration package (always possible: object variables are per
  class scope). Its subclasses and classes that INHERIT it in the package are interpreted too (reported). Its PUBLIC
  classes are published with the compiled ones.
- One method moves only when it shares no variables with the compiled class: no EXPOSE, not INIT / UNINIT, not an
  attribute. Otherwise prefer -> warning + compiled; requires -> build error. A rule that matches nothing: warning
  (prefer) / error (requires). The build prints every rule it honoured (`rx2cpp: interpreted: ...`).
- Code: `native/NativeInterpretedTable.cls`, `NativePackageParser.cls` (interpretedMethodLines), emitter
  (interpretedMethods / interpretedPublic). Test: `native/test_interpreted_table.sh` (all rules, refusals, all three forms, live edit of the file form).
- `interpreted_form tokenized | source | file` (one line per table; default **tokenized**, also with no table):
  - tokenized: `native/build.sh` builds the library, runs `rexxc` on the declaration package (rexxc resolves the
    EXTERNAL methods, so it runs against the library just built, with `RX2CPP_TOKENIZING=1` so the package prolog
    does not run at build time), embeds the image (`LoadPackageFromData` accepts a rexxc image) and relinks. Only
    `generated_package.cpp` is recompiled. Saves the parse at load; interpreted code runs at the same speed.
    While `RX2CPP_TOKENIZING` is set the library's loader does nothing: loading the declaration inside rexxc put live
    objects into the image (crypto: 481 KB image that crashed on load; now 155 KB). rexxc also loads every
    `::requires ... LIBRARY` dependency, so those must be on LD_LIBRARY_PATH for the build (archive -> compresslib).
    The declaration and its image are kept next to the library: `<lib>_declaration.cls` / `.rxc`.
  - source: the declaration is embedded as text and parsed at load.
  - file: interpreted parts go to `<lib>_interpreted.cls` next to the `.so`, read at every load and spliced in at
    `/* #REXX2CPP METHODS class */` / `/* #REXX2CPP CLASSES */` markers (one package, same semantics). Edit the file,
    reload, change is live. Missing file / missing or extra section -> load error, never a silent fallback.
- Not yet: the main-program lane (`build.sh prog.rex`) does not read the table; reloading a file-form library inside a
  running process (re-define methods on live classes) is not done.

```
OR=$(cat /tmp/claude-0/-home-claude-oorexx/*/scratchpad/orpath)
export OO_ROOT=$OR REXX_BIN=$OR/bin/rexx REXX_LIB=$OR/lib PATH=$OR/bin:$PATH LD_LIBRARY_PATH=$OR/lib REXX_PATH=$PWD
```

tokenized: compress 4/4, archive, json 284/284, Maths 11/11, crypto 8/8 SAME (ed25519 8.5 s vs interpreter 23.9 s).
Regression (about 40 minutes on 2 CPUs): every `tests/test_*.sh` and `native/test_*.sh`; `tests/test_kernel_objects.sh`
needs `RX2CPP_KERNEL=<kernel build dir>`.

Profiling a native library: build normally, then
```
valgrind --tool=callgrind --callgrind-out-file=x.cg rexx prog.rex
callgrind_annotate x.cg | head -60
```
`RX2CPP_BIF_STATS=1` prints, at exit, every BIF / String method / CALL that went to the interpreter and how often.
