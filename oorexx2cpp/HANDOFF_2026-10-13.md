## rx2cpp compiles itself

```
native/build_self.sh /path/to/outdir          # builds outdir/librx2cppc.so, then checks the fixed point
RX2CPP_COMPILER_LIB=/path/to/outdir native/build.sh pkg.cls outdir lib    # generate with the compiled compiler
```

- `build_self.sh` combines the compiler's own packages (the `::requires` of `rx2cpp_native_library.rex`: 72 files,
  5,018 lines, 85 classes) into `outdir/rx2cppc.cls` and builds `librx2cppc.so` with the native lane.
- Fixed point (checked on every build): the native compiler and the interpreted compiler each compile that source;
  all four outputs (generated.cpp ~2 MB, .hpp, package glue, declaration) and the compiler's own output must be
  byte-identical, else the script fails. Identical C++ means a stage-2 compiler is the same compiler.
- Fixed point at abdae83 (2026-10-23, security managers in): native 217 s, interpreted 300 s.
- Speed: compiling the compiler 55 s native vs 190 s interpreted. NotNotes nosql (16,301 lines): C++ generation
  about 4 minutes native; the interpreted compiler had not finished after 58 minutes.
- With `RX2CPP_COMPILER_LIB` set, `native/build.sh` runs `rx2cpp_native_library.rex` with its compiler packages
  replaced by `::requires 'rx2cppc' library`. The library must be rebuilt after any change to the rules/compiler.
- `RX2CPP_PROGRESS=1` prints per-phase / per-class timings of the generator to stderr.

## Performance: numeric code over collections (Josep Maria Blasco's grok.rex)

His report (39926e5): grok.rex's routines compiled, main program interpreted: identical numbers, 7.5 times slower
than interpreted; 52% of the time in EnvObject::sendMessage (every `E[a+1]`, `W1[j][i]` a message to the
interpreter). Reproduced from the oorexxwasm repository's grok-live.rex (drawing removed), 10 epochs:

| Build | Time | vs interpreted (13.8 s) |
|---|---|---|
| routines compiled, main interpreted, 39926e5 | 78.3 s | 5.7 x slower |
| + .Array [] / []= through ArrayAt / ArrayPut | 33.9 s | 2.5 x slower |
| everything compiled (the main program a routine of the library) + native Array FILL and Directory entries | 29.9 s | 2.2 x slower |
| + 128-bit arithmetic for small operands (small_math: addSub, multiplication rounding, formatting) | 27.5 s (routines only: 32.5 s) | 2.0 x slower |

- `[]` / `[]=` of an interpreter Array (the class itself, one-dimensional, with items) with a plainly written
  positive index: ArrayAt / ArrayPut instead of a message (no index or selector string, no index parsing; two
  interpreter entries instead of about six). Empty slots, other indexes, multi-dimensional and subclass arrays: the
  message. `native/test_collection_paths.sh`.
- A native Array's FILL, and a native Directory's entries as messages (`d~w1 = x`, `d~w1`: DirectoryClass::unknown,
  Directory methods first) no longer turn them into interpreter objects (which made every later access a message).
- Arithmetic: `+ - *` on plain operands of at most DIGITS digits under DIGITS <= 18 run NumberString::addSub and the
  multiplication's rounding on 128-bit integers and fixed buffers (`small_math`), not cpp_int and digit strings;
  anything else (longer operands, exponential results, LOSTDIGITS) takes the general path.
  `native/test_arith_oracle.sh` has a third family for it (`gen_small.rex`: DIGITS 1..18, rounding on most results).
- Numbers as the interpreter keeps them (2026-10-16), against a Release interpreter with the stack-base patch, 10 epochs
  (interpreted 4.0 to 4.3 s); instructions per epoch from callgrind:

## Performance: the IBM REXX compiler's techniques (2026-10-17)

Tom's brief: the IBM Compiler for REXX/370's big wins (stems as arrays, loop counters as machine integers, dual-state
variables, constant folding). Every one below keeps the interpreter's results byte for byte: each fast path checks its
case at run time and otherwise does exactly what the code did before.

- Stems as arrays (df0e307): a StemObject keeps the values of tails 1..n in a vector (rx::stemGet1 / stemSet1 for
  S.tail with one tail, RX_VSTEM: the stem's own entry read through the slot table); any other tail, the stem's
  default value and DROP keep the table semantics. Stem lock: a spin lock. Stems bench (200 000): interpreted 2.03 s,
  compiled 1.25 s -> 0.66 s. `native/test_stem_array.sh`.
- Tight-loop bench (`native/bench/loops.rex`: sum with //, nested loops, iterative fibonacci, a sieve on a stem,
  a WHILE loop; n = 3 000 000, Release interpreter 1.55 s):

  | Step | Compiled | Instructions (n = 300 000; interpreted 0.98 G) |
  |---|---|---|
  | before | 4.49 s | 3.51 G |
  | operators with their own entry (rx::opAdd ... opCmp, cmpTest); % // and exact / of whole numbers on int64 | 0.77 s | 0.75 G |
  | DO loops on a machine integer (rx::loopInts / loopHolds / loopStep) | 0.64 s | 0.59 G |
  | native registers (below), X = Y without a copy, the loop counter from its register | 0.26 s | 0.17 G |

  - Operators (OperatorRules): + - * / % // and the comparisons call rx::opAdd, opSub, opMul, opDiv, opIntDiv, opRem,
    opCmp (selector as written, for an object's own method); a condition that is one comparison is rx::cmpTest (a C++
    bool, no "1"/"0" value). Two NumCache whole numbers (at most 9 digits) under DIGITS >= 9 are worked as int64;
    anything else is the message sendBinaryOp sends.
  - Loops (StmtDo): a controlled loop whose start, BY and TO are whole numbers keeps n; each pass checks the variable
    still holds n (its register, else its value), steps n, writes it (a number made by arithmetic), tests n against
    TO. The variable assigned in the body, NUMERIC changed, a value leaving 9 digits: the message path from the
    variable's value, for the rest of the loop. `native/test_int_fastpaths.sh` (92 lines: overflow into exponent
    notation, DIGITS 2 and 5 inside loops, FUZZ, DROP, INTERPRET, internal routines, decimals, objects).
  - Native registers (rules/RxNative.cls, the IBM "dual-state" variables): each method body's slot table has an int64
    register per variable (LocalSlots nr / nk). Expressions of whole-number literals and simple variables with
    + - * / % //, unary - +, the non-strict comparisons and & | && \ of comparisons have a native form; V = expr and
    conditions run it, and the generic code when any operand or result is not a 9-digit whole number (so a decimal,
    exponent notation or an error comes out exactly as before). Every native write also writes the variable, so
    everything else reads it as before; registers are cleared by a generic assignment (its own), and by calls,
    messages, any other instruction, labels (SIGNAL, conditions, internal routine entry) and CALL ON handlers (all).
    Strict comparisons and concatenation use the characters: never native. X = Y is native only when Y's characters
    are its number's own (NumCache canonical: no leading zero, not -0), so '05' is copied as '05'. Methods with
    EXPOSE have none (another activity may change an object variable). RX2CPP_NO_NATIVE=1 turns them off.
    `native/test_native_registers.sh` (VALUE(), INTERPRET, PARSE, internal routines with and without PROCEDURE,
    SIGNAL ON SYNTAX / NOVALUE, logical values that are not 0 / 1, DIGITS / FUZZ).

Object lifetime (found by the self-compiled compiler, intermittently: "native object not initialized or root token
inaccessible: RXBIFCATALOG SIGNATURE"): the interpreter object of a natively created instance (made on demand when it
crosses) was referenced by nothing the collector sees, so a collection could run its UNINIT while compiled code still
held the instance or was sending to it. Now the interpreter object is pinned while any compiled reference
(NativeInstanceRef) exists, and for the length of every send / argument use (`ProxyHold`, `rxobj::Arg::hold`). Cost: a
cycle of such objects referring only to each other is never collected (no UNINIT). Fixed point re-checked (lib13).

Cycle collection (2026-10-21, architecture decision: a native cycle collector). Pinning made every cyclic structure of
compiled objects (the Rexx Parser's doubly linked element list) permanent: 20 MB per parse, and the interpreter's heap
grew until allocation dominated (pbench 6-8x slower than interpreted). Now:
- A state whose interpreter object holds nothing of its own (`stateDisposable`: a class in `directNewTable`, no UNINIT)
  is not pinned for compiled references, and an object adopted from the interpreter keeps no global reference: the
  interpreter collects the object when it holds it no more (its UNINIT detaches the state), and one is made again when
  compiled code sends it to the interpreter. An object a native entry returns is pinned until the next entry
  (`rxobj::returnPin`), so a collection cannot take it before the interpreter has it.
- `collectCycles` (native_package_template.cpp.in), CPython's algorithm: for every native state and every native
  container reachable from one (NativeInstanceRef, NativeArray, NativeDirectory, StemObject: `gcValues` / `gcFields`),
  the references from other states and containers are subtracted from its use count; what has some left is held from
  outside (a running method, a local variable, the interpreter's object through the token table) and is live with all
  it reaches; the rest is unreachable and its references are dropped (`gcClear`). It runs when 20000 states (or as many
  as survived the last run) have been made, and only while the calling thread is the one thread in compiled code
  (`rxobj::exclusiveNative`; a thread entering compiled code waits for it). `RX2CPP_GC_EVERY=n` collects every n
  states (tests), `RX2CPP_GC_STATS=1` prints each collection.
- Not collected: a cycle that passes through an interpreter object compiled code holds (a native object's field holding
  an interpreter collection or a stem shared with the interpreter that holds the native object again: the global
  reference is a root the native side cannot see through), and instances of classes with UNINIT, or with interpreter
  state (an interpreter parent or mixin): those keep the pin.
`native/test_cycle_collection.sh` (combined and one library per package); the object, array, directory, stem, guard,
reply, package and library tests pass with a collection every 3 states.
- A disposable state's interpreter object is watched through a WeakReference (`watchProxy` / `proxyLive`): the
  collection that finds it unreachable clears the reference before its UNINIT runs, so compiled code never hands the
  interpreter an object that is waiting for its UNINIT (which would then detach it from its state while the
  interpreter still used it: the self-compiled compiler lost RxBifCatalog's fields, "Object SPECS does not understand
  HASINDEX", compiling the Rexx Parser). A user UNINIT (compiled as RX2CPP_USER_UNINIT) keeps the pin.
- Rexx Parser benchmark (pbench, one pass, combined build, e0206e3): 93.4 s (interpreted 51.7 s; 277 s before the
  collector work). Its collections free nothing, and that is right: the 158292-element tree is live until the pass ends
  (`RX2CPP_GC_STATS=1`: ~6400 states held from outside, nearly all through an interpreter object, the rest reachable
  from them). The gain came from not pinning, which lets the interpreter's heap stay small.

  - `RX_VGETK` / `RX_VSETK` / ... go through `LocalSlots::get/find/set(k, vars, name)`: the frame entry when the pool
    has one for slot k, the VarSlot as before otherwise. Every by-name access (lookup, set, drop, VarSlot slow paths,
    VALUE / VAR / SYMBOL, INTERPRET, PARSE, `.context~variables`) finds a frame variable through `frameEntry`, so it is
    the same variable everywhere. Enumerations use `forEachVariable`. A copy of a pool copies its frame variables by
    name (it has no frame).
  - Object variables: a compiled class keeps the names its methods EXPOSE in `rx::FieldFrame` (as long as the object);
    a method's frame refers to them directly. gcFields / gcClear see them.
  - Fixtures variable_frame.rex (VALUE, DROP, INTERPRET, NOVALUE, PROCEDURE EXPOSE chains, recursion,
    `.context~variables`) and variable_frame_methods.rex.

## The interpreter epoch and environment symbols (2026-10-23)

Architecture: Tom Dyer ("trigger on change": cached objects passed while nothing changed; catch Directory SETMETHOD /
UNKNOWN, "it's only used in directory"). Coding: Claude.

- `include/rx_api_epoch.hpp`: while compiled code runs (from `rxobj::Scope`), the thread context's function table is a
  copy whose functions bump a counter (the epoch) before and after the interpreter's own. `RX_API_PURE` lists the
  functions that cannot run Rexx code or change a collection; every other function bumps (`RX_API_BUMPS`). Static
  asserts check both lists against the header (THREAD_INTERFACE_VERSION 103, the struct size). Entering and leaving
  compiled code bump; so do the method context's ForwardMessage and SetGuardOn/Off (`viaInterpreter`).
- Environment symbols (`.NAME`): `rx::envValue` keeps a value while the epoch has not moved, and only while none of the
  package LOCAL, .local and .environment computes that name: DirectoryClass::get answers its contents first and runs a
  SETMETHOD entry only for a name it has no entry for, so a name is computed when a directory has an UNKNOWN method or a
  SETMETHOD entry of that very name (`environmentEntriesOnly(t, name)`, StringTableAt on the method table). The two
  Directory fields are found at library load by calibration (`directoryFields`: a Directory given each in turn, the
  words that change), not by sending a message (an INDEX or HASMETHOD would run them). Fixture env_epoch.rex.
  (Until 6e783bc the test was "no method table at all": .environment always has one SETMETHOD entry, LOCAL
  (ActivityManager::getLocalRexx, Setup.cpp), so nothing was ever kept: 3.46 million lookups a parser pass.)
- A lookup that is kept runs no Rexx code, so its own API calls do not move the epoch (`rxobj::QuietEpoch`); before,
  every miss threw away every other symbol's value.
- Fixed classes (a class of the package, one it imports, a public class of the REXX package) are found once and kept.
  The package's CLASSES / PUBLICCLASSES / IMPORTEDCLASSES are copies (PackageClass::getClassesRexx), so they are taken
  once at library load, after the required libraries are imported (takeFixedClassTables), and read with StringTableAt:
  a lookup allocates nothing, as interpreted. Asking them at each first lookup (d9a3834..abdae83) allocated four
  collections, enough to change when the interpreter collected an object compiled code had just been given
  (test_object_lifetime.sh: collected after 1 GC instead of 2; fixed in c274209).

## Security managers in compiled code (2026-10-23)

Tom: "We use security managers extensively so want them working". Every check the interpreter makes is made, with
the same protocol (a result is required: 91.999; exactly 0 or 1: 34.903) and the same order. Fixtures
env_security.rex, security_manager.rex (identical to the interpreter).

- Which manager: an activation takes its package's manager when it starts (`rx::ActivationScope::security`,
  `securityAtActivationStart`); a manager set during the routine applies to activations started after it, as
  interpreted. The package's manager is read from PackageClass / SecurityManager fields found by calibration at load
  (`packageFields`). The instance manager of ooRexx 5.3 is never set (InterpreterInstance::setSecurityManager has no
  callers).
- LOCAL / ENVIRONMENT: every environment symbol, also `.RS .LINE .CONTEXT .METHODS` (the manager is asked first, an
  entry of that name wins, then the special value: `RX_ENV_SPECIAL`).
- CALL / COMMAND / METHOD: interpreter code run by compiled code goes through helper routines (`helperRoutine`), which
  are given the activation's manager before each CallRoutine; machinery helpers (`internalRoutine`) run without one.
  The helpers use no dot symbol of their own (RX2CPP_CALLER_CONTEXT, RX2CPP_TAKE: private routines of the library), so
  the manager sees no request the source did not make.
- METHOD: while a manager is active, `rxobj::send` to an interpreter object goes through a helper running under it
  (`rx2cpp_secured_send`), so protected methods are checked; compiled PROTECTED methods are not in the direct dispatch
  table. Cost: a helper call per send, only while a manager is active.
- STREAM: checked before a stream is opened (the answer is the STREAM entry).
- INTERPRET: the code object is made natively and its package given the activation's manager.
- Checked to match (fixtures security_same_activation.rex, security_internal_sends.rex): a protected method sent by
  the activation that set the manager is not checked, by a later routine it is; protected MAKESTRING / = reached by
  SAY, ||, LENGTH, a comparison and REQUEST are asked about (METHOD) exactly as interpreted.
- Not done: REQUIRES (package loading is the interpreter's); about 40 internal API sends of the runtime (CLASS, ID,
  PACKAGE queries) do not go through the secured path (none found to differ yet); if calibration fails, the FINDCLASS
  fallback cannot tell an entry set to .nil from a missing one.

## Interpreter bugs found (ooRexx 5.3 head, de1db87; reported to the ooRexx developers with a patch)

Status against trunk r13284 (2026-10-23): 1 fixed in r13257 (#2100); 2 still present, to be filed; 3 (bug 5 of
`BUG_REPORTS.md`) fixed in r13259 (#2102), before we found it; the SysStemSort crash (bug 4) fixed in r13284 (#2120);
the per-call /proc/self/maps read fixed in r13267 (#2106). Our interpreter is r13196: check trunk before any ticket.

Reproductions and the patch: `ootest/interpreter_bugs/` (`BUG_REPORTS.md`, `ooRexx-native-api-fixes.patch`).

1. `ReleaseGlobalReference` adds a global reference instead of removing one: `InterpreterInstance::removeGlobalReference`
   calls `memoryObject.addGlobalReference`. Every object native code ever referenced stays for good. rx2cpp no longer
   uses global references for values (pin table, above), so it is correct with or without the fix.
2. An argument error raised by `processArguments` of a native method (wrong count, unconvertible argument) when the
   caller is native code leaves the callee's NativeActivation on the activity stack with `argList` pointing at an
   unwound C stack: `CheckCondition()` in the caller is false, and the next garbage collection before the caller returns
   marks garbage and crashes (`NativeActivation::live`, `memory_mark_array(argCount, argList)`). Reproduced (3/3, with
   a control). Likely cause of the BSF4ooRexx crashes under object-creation pressure. rx2cpp compiled code is exposed
   the same way until the interpreter is fixed.
   Ticket ready: `ootest/interpreter_bugs/TICKET_bug2.md` with `ooRexx-native-arg-error.patch`, verified on a trunk
   a4210fc build (unpatched: segfault 3/3; patched: CheckCondition=1, no crash 3/3). Tom files.

3. (Found 2026-10-22; `ootest/interpreter_bugs/` bug 5: reproduction `uninitscan/uninitscan.rex`, patch
   `ooRexx-uninit-count.patch`; already fixed upstream in r13259, bug #2102: not to be filed.) `MemoryObject::checkUninit` counts every unreachable object in the uninit table
   as a new pending uninit (`pendingUninits++`), also one already marked ready by an earlier collection whose UNINIT has
   not run yet. `runUninits` subtracts one per UNINIT run, so the count can stay above 0 for good, and then
   `checkUninitQueue` (every RexxActivation and NativeActivation) scans the whole uninit table each time. A native
   method that allocates enough for two collections before returning triggers it. The compiled Rexx Parser spent 37% of
   its samples in `runUninits`. rx2cpp no longer gives compiled classes an UNINIT of their own (below), so the table
   holds only objects of classes with a user UNINIT. The fix: `if (... isObjectDead(markWord) && !uninitObject->isReadyForUninit())`; with it the
   reproduction's 100000 calls take 0.02 s instead of 9.19 s.

## Known differences that remain

- A compiled routine called by the interpreter cannot know its call type: PARSE SOURCE there is a run-time error.
- The stream table of a compiled routine called by the interpreter is its own (the interpreted caller's is not
  reachable from native code); compiled-to-compiled calls share it, as interpreted.

- A run-time error inside compiled code shows `*-* Compiled routine "A".` in the traceback instead of the source line.
- A failing command prints its TRACE NORMAL lines from the command helper (`rx2cppCommand`, helper line numbers)
  instead of the source clause; with TRACE OFF both are silent.
- An untrapped HALT / NOMETHOD raised by a compiled method into an interpreted caller is ignored (the native API has
  no way to raise it as RexxActivation::raise does: error 4.1 / 97.x); compiled callers get the error.
- CALL ON handlers of conditions raised inside an INTERPRET string run after the whole string (interpreted: at the
  string's own clause boundary).
- In a combined library all source files share one package, so a private class of one file is visible to the
  other files of the same library (the interpreter would hide it).
- FINDROUTINE answers of a compiled library's package are kept: a routine added to that package later by interpreted
  code (package~addRoutine) under a name already found is not seen by compiled code.
- SUPER as a value in a method (`say super`, VAR('SUPER')) is unset in compiled code; interpreted it is the scope's
  superclass. SELF~m:SUPER and FORWARD CLASS (super) are unaffected.
- `tests/test_extlib_repair_v028.sh` needs `RX2CPP_EXTLIB_ROOT` (external package, not present here).
- REPLY: the method's code before the REPLY runs on the method's own thread (interpreted: on the caller's), so it
  sees that activity's thread-local state; an untrapped error after the reply shows the compiled-frame traceback.
- GUARD WHEN re-evaluates its expression whenever another activity has run compiled code of the same object and
  scope (any release of its compiled-scope lock), not only when a variable of the expression changed: more
  evaluations than interpreted, the same outcome unless the expression has side effects.
